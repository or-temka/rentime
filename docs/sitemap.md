# Карта сайта

Поисковик узнаёт адреса страниц из карты сайта. Её пишет `next-sitemap` после сборки (`postbuild` в `package.json`). Правила лежат в `next-sitemap.config.js`.

`public/sitemap.xml`, `public/sitemap-0.xml` и `public/robots.txt` руками не правят: следующая сборка их перезапишет.

## Два файла

`sitemap.xml` — индекс. В нём нет страниц, только ссылка на файл со списком адресов. `sitemap-0.xml` — сам список.

Библиотека всегда пишет так. В конфиге `sitemapSize: 5000`: когда адресов станет больше, появятся `sitemap-1.xml`, `sitemap-2.xml` и так далее, а индекс на них укажет. Пока страница одна, индекс всё равно нужен.

В `robots.txt` указан только индекс (`https://rentime.ru/sitemap.xml`). Поисковик читает его и сам забирает `sitemap-0.xml`.

## Откуда берутся адреса

Три источника.

**Обычные страницы** с фиксированным маршрутом (`src/app/contacts/page.tsx` и такие же) сборка находит сама. Приоритет и частота задаются в `transform`:

| Страница | priority | changefreq |
|----------|----------|------------|
| `/` | 1 | weekly |
| `/contacts`, `/payment-and-delivery`, `/lease-terms` | 0.5 | monthly |
| остальные статические | 0.7 | monthly |

Картинки, `.json` и `.ico` в карту не попадают.

**Карточки товаров** динамические, сборка их не раскрывает. Список — `products.sitemap.json`: `id`, `priority`, `changefreq`. Каталог `/products` добавляется там же, priority `0.99`, weekly. Новый товар попадёт в карту только после записи в этот файл.

**Статьи** (инструкции) собираются из `.mdx` опубликованных товаров. Отдельный список не нужен.

Опубликованный товар — тот, что импортирован и записан в объект `PRODUCTS` в `src/entities/product/constants/products/index.ts`. Папка товара без этой записи в карту статей не попадает: страницы у неё нет.

| Файл | URL |
|------|-----|
| `index.mdx` | `/products/<id>/instructions` |
| `turn-off.mdx` | `/products/<id>/instructions/turn-off` |

Имя файла — slug: `a-z`, `0-9` и дефисы. У статей priority `0.6`, changefreq `monthly`.

## Как добавить ссылку

- Новая статическая страница — создать `page.tsx`. В карту попадёт сама.
- Новый товар — добавить объект в `products.sitemap.json`.
- Новая статья — положить `.mdx` в `instructions/` опубликованного товара. Если это не оглавление, ссылку на неё стоит добавить и в `index.mdx`.

После `npm run build` адреса появятся в `sitemap-0.xml`.

## Дата изменения

`lastmod` — дата последнего коммита, который менял исходник этой страницы. Поисковик смотрит на неё, только пока она совпадает с реальной правкой. Одна и та же метка у всех адресов после каждой сборки заставляет его метку игнорировать, поэтому дата сборки не используется.

Дата файла на диске тоже не подходит: Git её не хранит. После нового `git clone` у всех файлов становится время выгрузки, и карта снова говорит, что изменился весь сайт.

Что считается исходником:

| Адрес | Последний коммит среди |
|-------|------------------------|
| статья | её `.mdx` |
| карточка товара | файлов каталога товара, без папки `instructions` |
| `/products` | `products/index.ts`, каталогов опубликованных товаров (без `instructions`) и `src/app/products` |
| `/` | `src/app/page.tsx`, `page.module.scss` и `src/app/_components` |
| остальная страница | файлов её папки |

Вложенный маршрут считается отдельно. Правка `/legal/privacy/withdraw` не двигает дату `/legal/privacy`. Правка статьи не двигает дату карточки товара.

В файле время в UTC: коммит в 21:53 по Москве записан как `18:53Z`.

Если файла ещё нет в Git, берётся дата изменения на диске. Если сборка идёт из копии без папки `.git`, коммиты прочитать нельзя, и для всех файлов остаётся эта же запасная дата.
